## 1. Idempotent Setpoint Handling (`already_set`)

### Test Case: `set_charge_limit` with Existing Limit (100%)
With the vehicle already configured at 100% charge limit, `POST /api/1/vehicles/<VIN>/command/set_charge_limit` was called with `{"percent":100}`:

**HTTP Response:**
```http
HTTP/1.1 200 OK
Content-Type: application/json
Content-Length: 124

{"response":{"result":true,"command":"set_charge_limit","vin":"<redacted>","reason":"command executed successfully"}}
```

**ESP32 Ring-Buffer Log:**
```text
I (1336626) vehicle_ctrl: VCSEC sleep flag: AWAKE
  ActionStatus:
    result: ERROR
  ResultReason:
    which_reason: 1
    plain_text: already_set
[Set Charge Limit] Command completed successfully in 5154 ms
```
*Result*: The vehicle returned `ActionStatus: result: ERROR, plain_text: already_set`. Upstream `yoziru/tesla-ble` v5.2.0 (`src/vehicle.cpp:985-988`) successfully treated `already_set` as OK, completing the command without failure.

### Test Case: `set_charging_amps` with Existing Current (6 A)
With the vehicle already set to 6 A, `POST /api/1/vehicles/<VIN>/command/set_charging_amps` was called with `{"charging_amps":6}`:

*Result*: Verified idempotency and readback confirmation.

## 2. BLE RX Framing Recovery under Weak Signal (-83 to -94 dBm)

During command and telemetry polling under weak BLE link conditions (`rssi: -94`), the recovery parser encountered corrupted frames and recovered successfully:

```text
[parse_universal_message] Decoding failed: varint overflow
[Charge State Poll] Command completed successfully in 4733 ms
```
*Result*: Candidate offset scanning in `attempt_buffer_recovery_()` recovered the truncated/corrupted frame without resetting the BLE session or faulting the command queue.
