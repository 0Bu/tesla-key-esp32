# Technical feature catalog

What this firmware implements at the *platform* level — ESP-IDF capabilities, security mechanisms
and diagnostic surfaces that are not specific to Tesla, BLE or evcc. It answers "does this device do
X, and where does X live?" for someone who has not read the whole tree.

The Tesla-specific narrative (pairing, link state, telemetry, MQTT design) is in
[`ARCHITECTURE.md`](ARCHITECTURE.md), the trust and release pipeline in
[`SECURITY.md`](SECURITY.md), and the always-needed essentials in [`../AGENTS.md`](../AGENTS.md).
**Keep this file current when a technical feature lands or changes** — the canonical
[`$feature-docs`](../.agents/skills/feature-docs/SKILL.md) skill does that, and the runner-neutral gate
under [`tools/agent-hooks/`](../tools/agent-hooks/) gates a PR whose diff reaches one of the areas
below. Project policy has one versioned source: `AGENTS.md`, `.agents/` and the neutral hook/config
checkers.

Each entry says what the feature IS, where it lives and — the part that is easy to lose — *what
failure it exists to prevent*. A feature without that last part is one nobody can safely delete.

## 1. Boot, crash forensics and recovery

| Feature | Where | Prevents |
|---|---|---|
| Reset-reason capture | `main/diag_crash.cpp`, `logic/reset_reason.hpp` | A reboot nobody can attribute. Sampled once at boot; reported on `/status.sys.reset_reason`, MQTT and the syslog boot line. |
| Core dump to flash | `sdkconfig.defaults` (`ESP_COREDUMP_ENABLE_TO_FLASH`), `partitions.csv` (`coredump`, 48 KB at `0x12000`), `main/diag_crash.cpp` | A panic leaving no artifact. Crashed task, PC, backtrace and app-ELF hash are parsed once at boot; the raw image streams from `GET /coredump` for offline symbolisation. |
| Backtrace is Xtensa-only | `main/diag_crash.cpp` (`CONFIG_IDF_TARGET_ARCH_XTENSA`) | Publishing raw stack words as return addresses. ESP-IDF keeps an unwound PC array on Xtensa but only a raw stack dump on RISC-V. `/status.last_crash.backtrace[]` exists on esp32/esp32s3 only; on esp32c3/c6 reason, task, PC and ELF hash remain and an offline decoder unwinds the downloaded dump. |
| Orphan-dump erase | `logic/crashinfo.hpp` `coredump_is_foreign()` | Advertising a download the decoder will reject (the partition survives an OTA, so a dump may belong to an older build). Declared foreign only on PROOF, since erasing destroys the one artifact a panic left. |
| Crash report dismissal | `POST /crash/dismiss`, `main/diag_crash.cpp`, `logic/crashinfo.hpp` `crash_erase_permits_dismiss()` | A crash banner returning on every reload, or a dismissal racing MQTT/status readers. Erase first, then release-publish a separate atomic dismissal bit; the immutable `CrashInfo` is never written across tasks. `ESP_ERR_NOT_FOUND` (no `coredump` partition — every OTA-upgraded board) does not block dismissal; any other erase error does, because a dump may still be downloadable. |
| Boot-loop safe mode | `main/safe_mode.cpp`, `logic/boot_guard.hpp`, `main/vehicle_ctrl.cpp` `init_safe_mode`, `main/www/app.js` | A device that crashes its way out of reach. After 4 consecutive crash boots only WiFi + web UI + OTA start (no BLE/vehicle/MQTT), so recovery is a browser away, not a USB cable, and each boot stops re-opening the car's polling window. The controller starts inert but keeps best-effort read-only identity (`key_present`, `paired`, fingerprint); the fingerprint is computed lazily on first `/status` to keep an allocating mbedtls key parse off the recovery path, and an unopenable Tesla NVS namespace still boots with empty identity fields. The counter is safety-critical (an NVS error enters safe mode, never reads as zero) and safe mode **latches**: the 30 s healthy-boot timer is not armed there, since surviving with the crashing subsystems off proves nothing about the fault. Any non-fault reboot (OTA, saved rebooting config, power cycle) zeroes the counter only if that write succeeds. The UI shows a Safe Mode banner. |
| Heap watchdog | `logic/heap_watchdog.hpp`, `reboot_reason.hpp`, sampled in `vehicle_telemetry.cpp` | A wedge worse than a crash. INTERNAL `largest_block` < 4 KB for 5 unbroken minutes ⇒ deliberate restart with a `reboot_why=heap:<n>` breadcrumb, capped at 5, authorized only after the next counter is durably persisted. On the next boot only an exact missing key is ordinary; a read/erase failure or malformed breadcrumb closes at the cap and suppresses the vehicle activity window. Design: [ARCHITECTURE](ARCHITECTURE.md#heap-exhaustion-watchdog-last-resort-escalation). |
| Task watchdog (TWDT) | `sdkconfig.defaults` (60 s, `PANIC=y`), `vehicle_loop` and `mqtt_pub`; `mqtt_ha.cpp` feeds after each completed publish | The half the heap watchdog cannot see: a task blocked forever on a semaphore, BLE stack or socket while the heap looks healthy. Per-publish feeding lets a long but progressing discovery burst pass; a publish that never returns still cannot feed it. |
| Stack-overflow watchpoint | `sdkconfig.defaults` (`FREERTOS_WATCHPOINT_END_OF_STACK`) | A sparsely-writing frame stepping over the canary and corrupting a neighbour so the crash surfaces somewhere innocent; the watchpoint panics at the offending instruction. |
| Per-task stack-headroom telemetry | `main/stack_watch.cpp`; `http_server.cpp`, `vehicle_telemetry.cpp`, `vehicle_pairing.cpp`, `mqtt_ha.cpp`; `logic/status_model.hpp` | Finding out about frame growth only after the watchpoint panicked. Minimum free bytes since boot for `httpd`, `vehicle`, `auto_pair`, `mqtt`; presence is tracked separately so an unrun task is omitted while a genuine zero stays visible. |
| OTA rollback health gate | `logic/health_gate.hpp`, `main.cpp` `ota_health_gate_task`, `main/ota_update.cpp` (`OtaIdentityMutationGuard`, `OtaHealthCommitGuard`, `ota_config_restart_begin`) | Committing an image on the wrong evidence. Health = proven lease + 90 s uptime + INTERNAL largest block ≥ 4 KiB, so an image that dies under load, is critically fragmented or never gets online stays pending (past 600 s it is left pending without self-restart). Only a persisted rebooting `/set_mqtt`, `/set_syslog` or `/set_wifi` may confirm early after Ready/NimBLE-stable admission; timed and explicit confirmation share the `HealthCommit` owner and re-check heap, and a racing OTA/identity/FaultRestart owner keeps rollback armed. `/set_vin` and `/gen_keys[?force=1]` need a `Stable` image (else `503`); VIN/key and automatic identity/WiFi/heap recovery reboots are never health evidence. Setup-portal saves never reach Ready/NimBLE-stable admission and leave rollback armed; setup alone is not health evidence. Detail: [ARCHITECTURE](ARCHITECTURE.md#ota-self-update). |
| Essential-startup failure | `main/boot_fatal.hpp` (defined in `main.cpp`) | A half-initialised firmware pretending to run. When NVS, the vehicle controller, the LAN watchdog or a transport event group fails, a `PENDING_VERIFY` image actively rolls back (parking the task would wedge an unverified slot), while an already-valid image HALTS instead of looping, since a reboot loop reopens the car's polling window and erases the diagnostics that explain it. |
| Atomic vehicle-task start and runtime admission | `logic/task_start_gate.hpp`, `logic/runtime_admission.hpp`, `main/runtime_admission.cpp`, `vehicle_ctrl.cpp`, `vehicle_telemetry.cpp`, `vehicle_pairing.cpp`, `main.cpp` | A first task running against partially-created peers, an unsafe external delete on the other core, or a half-boot contacting the vehicle. Both entries wait before TWDT/mutex/BLE access; two creates release them together, a second-create failure is cooperatively acknowledged and self-deleted, and the global gate (`Booting → Ready/SafeMode/Fatal`) keeps vehicle-active HTTP/MCP/command paths failing closed until every essential service is up. |

## 2. Configuration and storage

| Feature | Where | Prevents |
|---|---|---|
| Atomic CRC config blob | `logic/config_store.hpp`, `main/config_blob.cpp` | A torn credential state. WiFi credentials + rollback backup + VIN + MQTT + Syslog are ONE CRC-checked `nvs_set_blob`, all-or-nothing across write failure and power cut. |
| Legacy per-key fallback | `logic/nvs_string_load.hpp`, `main/nvs_storage.cpp`, `main/config_blob.cpp` `cfg_load()`, `cfg_load_for_update()` | Stranding deployed devices' WiFi/VIN on the first OTA that introduces the blob; legacy keys are mirrored on save so a downgrade still finds them. The mirrors are best-effort and may be stale after a committed blob save, so the fallback is read-only: every read-modify-save route (`/set_vin`, `/set_wifi`, `/set_mqtt`, `/set_syslog`, `/set_ota`, the setup portal) loads through `cfg_load_for_update()` and refuses with HTTP 503 (nothing persisted) when the blob is unreadable or, with the blob absent (legacy layout), when ANY legacy key is unreadable, instead of writing a stale VIN, WiFi pair or service setting back. The refusal is deliberately all-or-nothing, because a partially read legacy snapshot is not a coherent identity: one unreadable key blocks every `/set_*` route and, while a VIN journal is armed, boot recovery. An explicitly empty legacy value remains valid. |
| `[[nodiscard]]` NVS writes | `main/nvs_storage.hpp` + `-Werror=unused-result` | A silently dropped write of something unrebuildable: the private key, the VIN, the safe-mode counter. |
| Exact fail-closed NVS registry | `logic/nvs_contract.hpp`, `main/nvs_storage.cpp`, `scripts/check-nvs-contract.py`, `test/test_nvs_storage.cpp` | An unknown or 16-byte key truncating onto an existing secret/session record, a key changing namespace/API/owner/retention unreviewed, or a new direct `nvs_*` call bypassing the adapter. All 19 records and the two tesla-ble long-name mappings are production-shared; mutation tests scan nested sources, headers and inline fragments. |
| Cached VCSEC session presence | `main/nvs_storage.{cpp,hpp}`, `main/vehicle_pairing.cpp` | The 50 ms vehicle loop probing flash-backed NVS to rediscover a stable bit. Save/remove update an atomic cache; read faults stay uncached and retry; only explicitly mapped long library keys are accepted. |
| WiFi credential rollback | `logic/wifi_rollback.hpp`, `main.cpp`, `POST /set_wifi` | An unrecoverable typo. A bad change self-heals to the last working network; only a SUSTAINED auth refusal spends the new credentials, while an absent SSID gets a 180 s grace. |
| Config survives OTA | `partitions.csv` (`nvs` at `0x9000`) | Losing pairing/keys on upgrade. Keep offset and size stable. |
| Shared WiFi credential contract + safe host provisioning | `logic/wifi_credentials.hpp`, `main/provisioning.cpp`, `main/http_config.cpp`, `main/net.cpp`, `provision.py`, `sdkconfig.defaults` | A setup surface accepting credentials the boot path can never use, or a generated partial NVS image replacing the whole partition and deleting the private key and sessions. All device paths share one byte-level open/WPA/raw-PSK contract; serial partition writes are retired; passwords come from a prompt, stdin or a 0600 file; setup is atomic. The image keeps WPA2/WPA3-Personal station support but does not link WPA-Enterprise, SAE-PK or WPA3-SoftAP paths the fixed credential model and open setup AP cannot reach (also keeps C6 below the next 64-KiB signing bucket); the build-contract gate pins all three exclusions. |
| MQTT broker test-before-persist + credential-free display | `logic/mqtt_uri.hpp`, `main/http_config.cpp` (`POST /set_mqtt`), `main/mqtt_ha.cpp` | Learning a broker is wrong only after saving and rebooting, exposing `user:pass@` through `/status`/UI/logs, or probing a different transport than the boot client. A changed non-empty broker must accept CONNECT before persistence (`400` refused credentials, `502` no answer, `503` not enough contiguous heap for a second TLS session, ~48 KB). Human-readable surfaces get only `mqtt_broker_display()`'s credential-free authority. |
| Fail-closed HTTP body, JSON and config intake | `logic/http_body.hpp`, `logic/vehicle_data.hpp`, `main/vehicle_ctrl.hpp`, `json_syntax.hpp`, `config_request.hpp`, `main/http_handlers.hpp` (`kQueryBufBytes`), `json_builder.hpp`, `json_http_reply.hpp`, `mcp_json_payloads.hpp`, `main/http_common.cpp`, `http_config.cpp`, `http_api.cpp`, `mcp_server.cpp`, `provisioning.cpp` | Empty body, oversized body, receive failure and OOM collapsing into one null pointer — turning a rejected config request into an intentional empty disable, hiding cJSON OOM as malformed input, executing a command from an unparsed body, truncating an embedded-NUL JSON-RPC id, or returning partial JSON with HTTP 200. Typed 2 KiB intake (400/413/503), separate 1024-byte `POST /save`, a 15 s monotonic body budget which progress cannot reset (plus at most one 5 s socket read), and read-side shutdown/connection retirement that prevents IDF cleanup from draining a slow rejected body, allocation-free syntax gate, sticky response ownership, and query strings length-validated against `kQueryBufBytes` (128 B, bounded by `CONFIG_HTTPD_MAX_URI_LEN`) so truncation cannot silently disable `redact` or `force`. Vehicle-data selectors reject unknown/duplicate/malformed domains with 400; each selected cache must be available for 200, including reported preconditioning presence. API climate data uses a fixed cache snapshot; energy remains a typed kWh number for evcc. Status mapping: [ARCHITECTURE](ARCHITECTURE.md#http-request-body-and-allocator-failure-contract). |
| Single-source HA discovery registry | `logic/mqtt_discovery_registry.hpp`, `main/mqtt_ha.cpp`, `mqtt_payloads.hpp`, `test/test_mqtt_json_publish.cpp` | One of the 55 entities silently reading a missing field, wrong domain/type, duplicate topic/`unique_id` or wrong binary inversion. Production derives component, topics, id and template from the IDF-free registry; the gate materializes every row against all full payloads. `safe_mode`/`crash_dump` are JSON booleans so `"OFF"` cannot evaluate truthy. |
| Fail-closed retained MQTT JSON | `main/mqtt_ha.cpp`, `mqtt_json_publish.hpp`, `mqtt_payloads.hpp`, `mqtt_publish_sequence.hpp`, `test/test_mqtt_json_publish.cpp`, `test/test_runtime_boundary_contract.py` | A partial retained document after cJSON OOM, lost ownership on a print failure, resuming after half a discovery sequence, or a ninth payload factory with no OOM/success case. Any build/print/publish failure publishes nothing and re-arms Discovery → availability → state; static policy requires definitions, calls and test cases to be equal sets; the allocation matrix is sanitizer-gated. An invalid domain cache overwrites its retained topic once with `{}` (`logic/mqtt_state_lifecycle.hpp`) and every `value_template` renders an absent field as `None` (`logic/ha_templates.hpp`), because HA keeps the previous state on an empty rendering — so old SOC/charging/lock readings cannot outlive the RAM cache. |
| Vehicle-stable HA identity | `logic/ha_identity.hpp`, `main/mqtt_ha.cpp` | A replacement ESP32 creating a second HA device and 55 new entities. The validated lowercase VIN anchors topics, `unique_id`s and the device identifier; only an invalid VIN falls back to the board MAC. |

## 3. Security

| Feature | Where | Prevents |
|---|---|---|
| Signed OTA (Secure Boot v2 RSA-3072, no hardware Secure Boot) | `sdkconfig.defaults`, `scripts/ci-build-all.sh`, `ci-sign-artifacts.sh`, `check-firmware-artifacts.py`, `ota-signing-public-key.sha256`, `release-relevance.sh`, `.agents/skills/usb-recovery/SKILL.md` | A compromised update host pushing unsigned firmware, a changed CI secret replacing the production authority, or an image with a bad signature/extra padding block. Compilation is unprivileged; only the protected signer holds the key, verifies every RSA-PSS signature (incl. the RFC 8017 RSAVP1 range), requires exactly one first-position block bound to the reviewed pin, and requires the minimal 64 KiB-aligned projection plus one 4 KiB sector. Flash, ship and USB-recovery repeat the app-only signature/pin check before a physical write (a development-key-signed local image is verified against that key). PR CI uses a disposable key with tamper/wrong-key/extra-padding canaries; the pin file is release-relevant. No OTA key-rotation path exists. Reversible, no eFuses. Details: [SECURITY](SECURITY.md#signed-ota-images). |
| Provenance-bound signed PR previews | `.github/workflows/signed-pr-preview.yml`, `pr-preview-cleanup.yml`, `.agents/skills/flash-esp32/SKILL.md`, `scripts/check-build-artifact-inventory.py`, `check-firmware-artifacts.py`, `reconcile-pr-previews.sh` | Trusting a PR producer's self-authored inventory, executing PR code in the privileged signer, signing fork/stale/different bytes or a wrong-base version, publishing a superseded head, testing hardware with a stale preview artifact, or leaving signed test firmware public after close/force-push/label removal. A secret-free exact-head rebuild and the original build both feed the protected job, which never checks out the PR, re-derives the version and accepts only byte-identical manifests + 53 payloads; every app is re-verified against the pin before publication. The hardware artifact is named by PR plus full head SHA. Flow: [SECURITY](SECURITY.md#release-pipeline-and-trust-boundaries). |
| Transactional key rotation + VIN journal | `main/vehicle_pairing.cpp`, `main/vehicle_ctrl.cpp`, `logic/key_rotation.hpp`, `logic/vin_transition.hpp`, `main/main.cpp` | Reporting a failed rotation as success, reusing old sessions after a durable replacement key, showing the previous key's creation date for a newly rotated key, or a power cut leaving a new VIN with the previous vehicle's key/session. `tk::regenerate_private_key()` (2048 B PEM export, never replaces a key it cannot export) is run against the real tesla-ble by `test/test_tesla_ble_harness.cpp`; `tesla_ble/key_rotate` blocks boot/signing until cleanup completes (an unreadable probe fails closed) and retires an untrusted `key_created` timestamp before journal removal (both erase sequences are host-tested against the real NVS adapter); `tesla_cfg/vin_txn` drives deterministic recovery. |
| Tesla protocol and patch known-answer gate | `test/tesla_protocol_vectors.test.mjs`, `test/test_tesla_ble_harness.cpp`, `scripts/test-tesla-ble-harness.sh`, `patches/tesla-ble/`, `dependencies.lock.*`, `main/vehicle_pairing.cpp`, `scripts/check-dependency-contract.py` | A dependency or local patch that still compiles but changes the VIN advertisement hash, P-256 ECDH byte order, `session info` HMAC label, AES-GCM metadata/AAD/nonce/tag layout, the NVS PEM format or signer.go counter alignment; a response AAD built from the request counter (which fails every counted response once patch 0006 verifies the tag); or an ESP-IDF bump leaving the proof on stale crypto (`check-dependency-contract.py` requires the harness's `MBEDTLS_REF` to equal its pin and, in the pinned image, ESP-IDF's mbedtls checkout to match). The series is patches 0004 (drop unused Parental Controls arms, a pure deletion disjoint from tags `vehicle_commands.cpp` builds), 0005 (session-counter replay alignment) and 0006 (PSA crypto port); the harness proves the V1 vectors byte for byte (see [test/README](../test/README.md#beyond-the-pure-logic-binary), [ARCHITECTURE](ARCHITECTURE.md#pinned-tesla-ble-and-native-orchestration)). Patches 0001–0003 are retired in favor of native `main/logic/` orchestration. Public canonical keys only; no device or vehicle secret enters CI. |
| Generation-bound deferred BLE command readiness | `logic/ble_readiness.hpp`, `ble_deferred_event.hpp`, `main/ble_client.{cpp,hpp}`, `vehicle_ctrl.cpp`, `vehicle_telemetry.cpp` | Treating a GAP handle as command-ready before service/characteristic discovery, CCCD acknowledgement and task-owned link activation; re-entering allocating/throwing Vehicle/NVS code from the hidden NimBLE host; or applying stale RX after handle reuse. The host copies bounded LinkUp/LinkDown/RX records into a static queue; `vehicle_loop` rejects stale generations, applies ordered down barriers and publishes readiness only after native orchestration acknowledges the exact generation. Overflow, oversize RX or an exception drops the link fail-closed. Persistent telemetry callbacks publish trivially-copyable latest values, and a separate charging-amps feedback generation keeps readback-before-completion semantics. |
| Deterministic BLE RX/TX framing | `logic/rx_framing.hpp`, `main/vehicle_ctrl.hpp`, `vehicle_telemetry.cpp`, `test/test_tesla_ble_harness.cpp` | Upstream's heuristic recovery loops, offset shifting and log floods on corrupt/split frames, and outgoing frames the car cannot decode (a second length prefix). Strict 2-byte BE length reassembly with a bounded buffer, inter-chunk timeout (3000 ms as configured by `tk::CommandRunner`; `ble.go` uses 1 s, an ADR-0005 departure) and immediate drop on implausible lengths (0 or > 2048); TX writes builder output unchanged (`tk::build_ble_tx_frame`) and refuses malformed frames. |
| Bounded BLE command runner | `logic/command_runner.hpp`, `ble_dispatcher.hpp`, `session_state.hpp`, `main/vehicle_ctrl.hpp`, `vehicle_commands.cpp`, `vehicle_telemetry.cpp` | Command timeouts, unbounded queue growth, blocking during prerequisite setup, lost wake arbitration. An 8-entry FIFO arbitrates VCSEC auth → wake → infotainment auth → payload, with exponential retry backoff, per-command wake policy (`NoWakeSkip`, `NoWakeFail`, `WakeIfNeeded`; wake confirmed only while awaiting it and re-evaluated on retry), nominal `already_set` handling, and direct `TeslaBLE::Client` encoding that bypasses `TeslaBLE::Vehicle`. Encrypted VCSEC status reaches decoding/callbacks only with initialized session/request context, successful authentication and a fresh response counter; intended plaintext broadcasts remain accepted. |
| Acknowledged NimBLE host startup | `logic/nimble_start_gate.hpp`, `main/ble_client.{cpp,hpp}`, `main.cpp`, `ota_update.cpp` | Treating ESP-IDF's void `nimble_port_freertos_init()` (5.5, unchanged in 6.1) as proof its hidden host task exists, reopening runtime after a late sync callback, or confirming OTA after an admitted host reset. Boot waits for the real sync callback with a terminal timeout; a saturating per-boot reset counter lets OTA health recheck sync and reset evidence. |
| Downgrade gate + manifest/image match | `main/ota_update.cpp` | A signed but OLD image carrying a patched flaw (a signature proves authenticity, not freshness), and a host advertising 1.9.0 while serving 1.8.0. The image's own version must equal the manifest's and pass the shared channel/PR policy: ordinary stable updates must be newer, with explicit same-core preview/Dev transitions and return-to-Release exceptions; the manifest is re-fetched on the update path so a direct caller is gated too. |
| Bounded exact OTA manifest intake | `logic/ota_contract.hpp`, `ota_changelog_range.hpp`, `main/ota_manifest.hpp`, `ota_update.cpp`, `http_ota.cpp`, `main/www/app.js` | A truncated/chunked/lying response, duplicate `version`, trailing JSON, over-nesting, decoded U+0000, huge numeric core or attacker-sized version becoming ambiguity, integer overflow or contiguous-heap failure. Complete non-empty body ≤ 8192 B, exact `Content-Length`, allocation-free syntax before cJSON, unique root keys, canonical version ≤ 31 B before copy, early body release. PR-preview targeting (`?pr=<N>`) validates positive integers, requires the `PR-<N>` suffix and a non-downgrading core; sibling changelogs are bounded at 1024 B and range-filtered for `GET /ota/changelog`. |
| Coherent allocation-free OTA status lock | `main/ota_update.cpp`, `test/test_runtime_boundary_contract.py` | A first-use lock allocation failure exposing unprotected status, mixed-generation fields, or `std::string` allocation under the status mutex. Readers copy one fixed POD snapshot; a completed check replaces all public fields at once; strings materialize only after unlock. |
| OTA update channel (Release vs Dev) | `logic/ota_contract.hpp`, `main/ota_update.cpp`, `http_ota.cpp`, `http_config.cpp`, `main/www/` | Installing unstable dev builds on production devices, or being unable to test `main` without manual builds. The channel lives in reserved `ConfigBlob` flag bits (older builds such as v1.5.7 decode it without wiping credentials). Dev is monotonic within the selected Dev channel; explicit returns from Dev to Release can use an older stable core, and PR/pre-release-to-stable and stable-to-Dev transitions may share a core. Targeted PR previews must match their PR number and use a non-downgrading core. |
| Firmware card: channel modal + on-demand check | `main/www/app.js`, `index.html`, `test/web_ui_http.test.mjs` | Accidental channel selection, unrequested dialogs while up to date, or installing without reading release notes. `#verLink` opens `#chanModal` (persists via `POST /set_ota`, then checks); `#fwCheckBtn` checks on demand (a toast if current) and opens `#otaModal` — version transition, channel, changelog from `GET /ota/changelog` — only if eligible under the selected channel/PR policy. Re-selecting the active channel is a no-op; `isOtaBusy()` locks the controls; a refused `POST /set_ota` rolls the selection back with the device's reason, and a timeout re-reads `/status`. |
| Bug-report redaction | `logic/redact.hpp`, `GET /status?redact=1`, `GET /diag?redact=1` | A snapshot carrying VIN, SSID, IP, vehicle/nearby BLE MACs, advertised names, broker or syslog host into a public issue. Fails closed: substitutes the value and keeps the key; `sys.board_mac` deliberately stays visible. `/diag` uses fixed-buffer whole-line framing, discards a wrapped ring's markerless first fragment and collapses any > 288 B line to `<redacted>`. The line table must cover every private-value log statement (including the request URI with the VIN): a new VIN/SSID/host-bearing log line needs a rule and test in the same commit. |
| Device-bound browser mutation gate | `logic/http_origin.hpp`, `main/http_server.cpp` | A foreign or DNS-rebinding site using a LAN user's browser to rotate keys, reconfigure, command, erase diagnostics or OTA. Browser mutations fail before dispatch unless Host is the device name/current IP and Origin matches; covers primary HTTP/MCP POSTs and their state-changing legacy GET forms; the separate open setup portal has its own physical-range boundary. Those are classified from the raw query with keys case-insensitive and values exact/undecoded, exactly as `esp_http_server` reads them — a case-sensitive match once left `?CLEAR=1`, `?VERBOSE=` and `/coredump?CLEAR=1` ungated while the handler still acted, and host cases pin both halves. Headerless POST clients (evcc, curl) stay compatible, while mutating GETs accept matching Origin/Referer or allowed fetch provenance; without it they require an explicit custom header (`X-Requested-With`) or a POST alias (`POST /ota/check`, `POST /diag`, `POST /coredump`): browser-CSRF hardening, not authentication. |
| Private wake capture | `scripts/capture_wake.py` | A full VIN and raw authenticated BLE frames landing as a commit-ready 0644 file. Default capture is VIN/frame-redacted in a fresh 0700 temp dir with a 0600 file; full bytes need `--include-sensitive`; verbose logging is enabled and cleanly restored via `POST /diag` in `finally`. |
| Restricted setup-AP surface | `main/provisioning.cpp` | The open setup AP exposing `/gen_keys`, `/diag`, `/status` or the command API; only provisioning routes exist in AP mode. |
| Charging-Manager-only key role | `vehicle_pairing.cpp` | Enrolling a key with door/body privilege the integration does not need. |

No HTTP auth or TLS on the device API, by design — evcc cannot send credentials, so the device is
trusted-LAN only ([`SECURITY.md`](SECURITY.md#http-api-exposure)).

## 4. Network

| Feature | Where | Prevents |
|---|---|---|
| Captive portal | `main/provisioning.cpp`, `logic/captive.hpp` | A setup portal that does not pop. DNS catch-all, a **302 redirect** on the three OS probe paths (a 200 + page may leave Android undecided) and RFC 8910 DHCP option 114 — three independent ways for a client to find it. |
| SPI Ethernet (W5500) | `net.cpp` (`CONFIG_TESLA_ETH_ENABLED`), `logic/eth_board.hpp`, `main/Kconfig.projbuild`, `sdkconfig.defaults.esp32s3`, `main/idf_component.yml` (`espressif/w5500`, esp32s3 only) | Running the BLE proxy on a radio that shares ONE antenna path with BLE. ### Why there is no static analyser (measured, not assumed)

Read this before proposing one. Measured on this tree with clang-tidy 18:

- **Blanket config:** 3355 findings, dominated by noise (769 `llvmlibc-callee-namespace`, 599
  `altera-unroll-loops`, 598 `pro-type-vararg` + 593 `avoid-do-while`, the last two almost entirely the
  project's own `CHECK` macro).
- **Curated to bug-finding checks** (`bugprone-*`, `clang-analyzer-*`, `cert-*`, `performance-*`):
  **3 findings, none in `main/logic/`** — two `cert-err33-c` on `snprintf` in the test file's golden
  emitter and one `bugprone-easily-swappable-parameters` on a test lambda.
- **`-Wconversion`:** 3 hits, all `int`→`float` in the two colour-gradient `lerp8` helpers, exact over
  their range. **`-Wshadow`, `-Wsign-conversion`:** zero.

The yield is low for a structural reason: the bug classes are typed out rather than linted out, and
the defects this project ships fixes for — a wrong link-state transition, a stale cache served as
fresh, a heap budget — are not in a linter's language. There is deliberately **no `.clang-tidy`
file**: an inert config reads like a guarantee while doing nothing. The survey did find the opposite
gap: `main/logic/` was never the exposed half (`-Wall -Wextra -Werror`, 3400+ host-tested checks),
`main/*.cpp` was, and its warning policy is now pinned in `main/CMakeLists.txt`.
