# Technical feature catalog

What this firmware implements at the *platform* level — the ESP-IDF capabilities, security
mechanisms and diagnostic surfaces that are not specific to Tesla, BLE or evcc. It is the answer to
"does this device do X, and where does X live?", asked by someone who has not read the whole tree.

The Tesla-specific narrative (pairing, link state, telemetry, the MQTT entity list) lives in
[`ARCHITECTURE.md`](ARCHITECTURE.md); the always-needed essentials are in
[`../AGENTS.md`](../AGENTS.md). **Keep this file current when a technical feature lands or
changes** — the canonical [`$feature-docs`](../.agents/skills/feature-docs/SKILL.md) skill does
that, and the runner-neutral gate under [`tools/agent-hooks/`](../tools/agent-hooks/) gates a PR
whose diff reaches one of the areas below. Project policy has one versioned source: `AGENTS.md`,
`.agents/`, `.codex/`, and the neutral hook/config checkers.

Each entry says what the feature IS, where it lives, and — the part that is easy to lose — *what
failure it exists to prevent*. A feature without that last part is one nobody can safely delete.

## 1. Boot, crash forensics and recovery

| Feature | Where | Prevents |
|---|---|---|
| Reset-reason capture | `main/diag_crash.cpp`, `main/logic/reset_reason.hpp` | A reboot nobody can attribute. The reason is sampled once at boot and reported on `/status.sys.reset_reason`, over MQTT and in the syslog boot line. |
| Core dump to flash | `sdkconfig.defaults` (`ESP_COREDUMP_ENABLE_TO_FLASH`), `partitions.csv` (`coredump`, 48 KB at `0x12000`), `main/diag_crash.cpp` | A panic leaving no artifact. The crashed task, PC, backtrace and app-ELF hash are parsed ONCE at boot; the raw image streams from `GET /coredump` for offline symbolisation. |
| **Backtrace is Xtensa-only** | `main/diag_crash.cpp` (`CONFIG_IDF_TARGET_ARCH_XTENSA`) | Publishing raw stack words as if they were return addresses. IDF declares `esp_core_dump_bt_info_t` per ARCHITECTURE: Xtensa carries an unwound PC array, RISC-V a raw stack dump (no windowed registers, so IDF cannot unwind on-device). On esp32/esp32s3 `/status.last_crash` carries `backtrace[]`; on esp32c3/c6 it does not — reason, task, PC and the ELF hash still do, and the full stack is in the downloadable dump, where an offline decoder unwinds it properly. |
| Orphan-dump erase | `logic/crashinfo.hpp` `coredump_is_foreign()` | Advertising a download the decoder will reject: the coredump partition survives an OTA, so a dump can belong to a previous build. Declared foreign only on PROOF, since the erase destroys the one artifact a panic left. |
| Crash report dismissal | `POST /crash/dismiss`, `main/diag_crash.cpp`, `logic/crashinfo.hpp` `crash_erase_permits_dismiss()` | A crash banner that comes back on every page reload, or an HTTP dismissal racing MQTT/status while they copy the boot-time strings/backtrace. Erase first, release-publish a separate atomic dismissal bit second; the otherwise immutable `CrashInfo` is never written across tasks. The one erase result that does NOT block it is `ESP_ERR_NOT_FOUND`: the device has no `coredump` partition, which is the state of every OTA-upgraded board, and there is simply nothing to destroy. Every other error still blocks, because then a dump may still be downloadable. |
| Boot-loop safe mode | `main/safe_mode.cpp`, `logic/boot_guard.hpp` | A device that crashes its way out of reach. After 4 consecutive crash boots it starts WiFi + web UI + OTA only, skipping BLE/vehicle and MQTT, so recovery is a browser away instead of a USB cable. Also stops each boot re-opening the car's polling window, which is what drains a parked battery. The counter is safety-critical: an NVS read/write error enters safe mode instead of being mistaken for zero or a successful latch. It **latches**: the healthy-boot timer that clears the counter is not armed while safe mode is active, because surviving 30 s with the crashing subsystems switched off is evidence about the recovery surface, not about the fault — arming it there would give a 4-crashes-then-one-quiet-boot cycle rather than a latch. Any non-fault reboot (an OTA install, a successfully saved rebooting configuration, a power-cycle) zeroes the counter only when that write succeeds, so it ends when someone acts on it and persistence is healthy. |
| Heap watchdog | `logic/heap_watchdog.hpp`, `reboot_reason.hpp`, sampled in `vehicle_telemetry.cpp` | The wedge that is worse than a crash: internal `largest_block` under 4 KB for 5 unbroken minutes ⇒ deliberate restart with a `reboot_why=heap:<n>` breadcrumb, capped at 5. The restart is authorized only after the next counter is durably persisted; save failure leaves the device degraded without rebooting. On the next boot, only an exact missing key is ordinary: read/erase failure or a malformed/out-of-range breadcrumb fails closed at the cap and suppresses the vehicle activity window. |
| Task watchdog (TWDT) | `sdkconfig.defaults` (60 s, `PANIC=y`), subscribed by `vehicle_loop` and `mqtt_pub`; `mqtt_ha.cpp` feeds after each completed publish | The half the heap watchdog cannot see: a task blocked forever on a semaphore, the BLE stack or a socket, with the heap looking perfectly healthy. Per-publish progress feeding prevents a long but progressing discovery burst from looking like one wedged operation; a publish that never returns still cannot feed it. |
| Stack-overflow watchpoint | `sdkconfig.defaults` (`FREERTOS_WATCHPOINT_END_OF_STACK`) | A sparsely-writing frame stepping over the canary and corrupting a neighbour, so the crash surfaces later somewhere innocent. The watchpoint panics at the offending instruction. |
| Per-task stack-headroom telemetry | `main/stack_watch.cpp`, sampled in `http_server.cpp`, `vehicle_telemetry.cpp`, `vehicle_pairing.cpp` and `mqtt_ha.cpp`; reported by `logic/status_model.hpp` and `mqtt_ha.cpp` | Discovering frame growth only after the stack watchpoint has already panicked. The historical minimum free bytes since boot are visible for the four allocation-rich application paths; sample presence is tracked separately so a task that has not run is omitted while a genuine zero-byte measurement remains visible. |
| OTA rollback health gate | `logic/health_gate.hpp`, `main.cpp` `ota_health_gate_task`, `main/ota_update.cpp` `OtaIdentityMutationGuard`, `OtaHealthCommitGuard` | Committing an image on the wrong evidence or crossing a persisted fault-restart window. Health is a PROVEN LINK plus a 90 s uptime floor and INTERNAL largest block ≥4 KiB — so an image that dies under load, is already critically fragmented, or never gets online remains pending. The offline case is the one no later OTA could repair. Past 600 s an unhealthy image is left pending without self-restart, so the next reboot rolls it back. A successfully persisted rebooting `/set_mqtt`, `/set_syslog`, `/set_wifi` or setup-portal save may confirm early, but timed and explicit confirmation both acquire the shared HealthCommit owner and re-check heap after admission; a racing OTA/identity/FaultRestart owner or critical sample leaves rollback armed. `/set_vin` and `/gen_keys[?force=1]` are admitted only when the image is already Stable and the owner is idle; PendingVerify/unknown/active work returns 503 before mutation. VIN/key and automatic identity/WiFi/heap recovery reboots are not health evidence. Credential-less wireless setup mode is legitimately offline but still must pass the heap gate. |
| Essential-startup failure | `main/boot_fatal.hpp`, defined in `main.cpp` | A half-initialised firmware pretending to run. When something essential fails to come up (NVS, the vehicle controller, the LAN watchdog, a transport's event group) a PENDING OTA image actively rolls back — merely parking the task would wedge the device on an unverified slot until someone resets it — while an already-valid image HALTS instead of rebooting, because a reboot loop re-opens the car's polling window on every boot and erases the in-memory diagnostics that would explain it. |
| Atomic vehicle-task start and runtime admission | `logic/task_start_gate.hpp`, `logic/runtime_admission.hpp`, `main/runtime_admission.cpp`, `main/vehicle_ctrl.cpp`, `main/vehicle_telemetry.cpp`, `main/vehicle_pairing.cpp`, `main/main.cpp` | A first FreeRTOS task running against partially-created peers/services, an unsafe external delete on the other core, or a half-boot contacting/waking the vehicle. Both task entries wait before TWDT/mutex/BLE access; two creates release them together, while a second-create failure is cooperatively acknowledged and self-deleted. They then remain blocked until every essential service makes the global gate Ready; SafeMode/Fatal and vehicle-active HTTP/MCP/command/telemetry paths fail closed. TWDT ownership unwinds before task exit. |

| Shared WiFi credential contract + safe host provisioning | `logic/wifi_credentials.hpp`, `main/provisioning.cpp`, `main/http_config.cpp`, `main/net.cpp`, `provision.py`, `sdkconfig.defaults` | One setup surface accepting credentials the boot path can never use — including the former open-network mismatch — or a generated partial NVS image replacing the entire partition and silently deleting the vehicle private key/sessions. | MQTT broker test-before-persist + credential-free presentation | `logic/mqtt_uri.hpp`, `main/http_config.cpp` (`POST /set_mqtt`), `main/mqtt_ha.cpp` | Learning a broker is wrong only after saving it and rebooting, exposing embedded `user:pass@` through `/status`, the UI or diagnostics, or probing a different effective transport than the boot client. A changed non-empty broker must accept CONNECT before persistence; 400 separates refused credentials from 502 no response. The client retains the full URI while human-readable surfaces receive only `mqtt_broker_display()`'s credential-free authority. The probe refuses itself with 503 when the largest contiguous INTERNAL block cannot afford a second TLS session (~48 KB). |
| Fail-closed HTTP body, JSON and config intake | `logic/http_body.hpp`, `logic/json_syntax.hpp`, `logic/config_request.hpp`, `main/json_builder.hpp`, `main/json_http_reply.hpp`, `main/mcp_json_payloads.hpp`, `main/http_common.cpp`, `main/http_config.cpp`, `main/http_api.cpp`, `main/mcp_server.cpp`, `main/provisioning.cpp` | Collapsing an empty body, an oversized body, a receive failure and allocator exhaustion into the same null pointer — which could turn a rejected config request into an intentional empty-string disable, hide cJSON OOM as malformed input, execute a command from a body that was never parsed, truncate an embedded-NUL JSON-RPC ID, or return a partial JSON object with HTTP 200. Normal REST/MCP intake has the typed 2 KiB path (400/413/503); the setup portal's separate `POST /save` reassembles at most 1024 bytes in a fixed buffer and maps empty/oversized input to 400. Syntax, the 16-container limit and unsupported U+0000 are classified allocation-free before materialization; input owners are released before blocking work; and request IDs use bounded fixed storage. Sticky ownership plus the shared print/send seam discards the complete response after any Create/Add/print failure. Nth-allocation tests run the real full status, tools/list and double-print state producers against the exact pinned cJSON source. |
| Single-source Home Assistant discovery registry | `logic/mqtt_discovery_registry.hpp`, `main/mqtt_ha.cpp`, `main/mqtt_payloads.hpp`, `test/test_mqtt_json_publish.cpp` | One of the 55 entities silently reading a missing field, the wrong domain/type, a duplicate config topic/`unique_id`, stale metadata or an incorrect binary inversion. Production derives component, topics, ID and template from the IDF-free registry; the gate materializes every row against all full domain payloads and pins field type, metadata and domain-topic mapping. `safe_mode`/`crash_dump` are JSON booleans, preventing non-empty `"OFF"` from evaluating truthy and reporting a false problem. |
| Fail-closed retained MQTT JSON | `main/mqtt_ha.cpp`, `main/mqtt_json_publish.hpp`, `main/mqtt_payloads.hpp`, `main/mqtt_publish_sequence.hpp`, `test/test_mqtt_json_publish.cpp`, `test/test_runtime_boundary_contract.py` | Publishing a partial retained discovery/state document after cJSON OOM, losing ownership on a print/build failure, resuming with state after only half a discovery sequence, or adding a ninth production payload factory with no OOM/success case. Production and the gate share Discovery plus all seven state-domain emitters; full/minimal optional branches, build, print and broker-publish failures publish nothing, short-circuit Discovery → availability → state, and rearm the full sequence. Static policy derives definitions, production calls and test cases as equal sets; the pinned-cJSON allocation matrix plus retained publish spy is sanitizer-gated. |
| Cached VCSEC session presence + fail-closed NVS key mapping | `main/nvs_storage.{cpp,hpp}`, `main/vehicle_pairing.cpp` | A 50 ms vehicle loop repeatedly probing flash-backed NVS merely to rediscover a stable session bit, or an unknown key longer than NVS's 15-character limit silently truncating onto another key/session record. Successful session save/remove operations update the atomic cache; read faults stay uncached and retry. Only explicitly mapped long library keys are accepted. |
| Vehicle-stable Home Assistant identity | `logic/ha_identity.hpp`, `main/mqtt_ha.cpp` | A replacement ESP32 creating a second HA device and 55 new entities. The validated, lowercased VIN anchors MQTT state/discovery topics, every discovery `unique_id`, and the HA device identifier; only an unprovisioned/invalid VIN temporarily falls back to the board MAC. |

## 3. Security

| Feature | Where | Prevents |
|---|---|---|
| Signed OTA (Secure Boot v2 RSA-3072, no hardware Secure Boot) | `sdkconfig.defaults`, `scripts/ci-build-all.sh`, `scripts/ci-sign-artifacts.sh`, `scripts/check-firmware-artifacts.py`, `scripts/ota-signing-public-key.sha256`, `scripts/release-relevance.sh` | A compromised update host pushing unsigned firmware, a changed CI secret replacing the production authority, or an accepted image carrying a bad signature/extra aligned padding block. Compilation is unprivileged; only the protected signing job gets the key. The signer verifies every RSA-PSS signature, requires exactly one first-position block, binds its public-key digest to the reviewed production pin, and requires the minimal 64 KiB-aligned projection plus one 4 KiB sector. The downloaded signed-preview/main/Release paths in the flash, ship and USB-recovery procedures repeat that app-only signature/pin check before a physical write; an explicitly development-key-signed local image is verified against that development key instead. Metadata and size alone are insufficient. PR CI uses a disposable key and tamper/wrong-key/extra-padding canaries. The authority-pin file itself is release-relevant, so a reviewed pin transition cannot be hidden behind an older Release/Pages baseline. Software-only TOFU has no OTA key-rotation path; pin/key changes require a separately reviewed USB fleet migration. Reversible, no eFuses burned. Details: [`SECURITY.md`](SECURITY.md). |
| Provenance-bound signed PR previews | `.github/workflows/signed-pr-preview.yml`, `.agents/skills/flash-esp32/SKILL.md`, `scripts/check-build-artifact-inventory.py`, `scripts/check-firmware-artifacts.py`, `scripts/ota-signing-public-key.sha256`, `.github/workflows/pr-preview-cleanup.yml`, `scripts/reconcile-pr-previews.sh` | Treating a PR producer's self-authored inventory as trusted source attestation, executing a PR checkout in the privileged `workflow_run` signer, signing fork/stale/different bytes or a regex-valid preview based on the wrong stable release, publishing with a changed signing authority, publishing a superseded head after review, selecting a stale preview artifact for physical testing, or leaving signed test firmware public after close/force-push/label removal. The default-branch `workflow_run` launches a separate exact-head rebuild with no repository/Environment secrets, write/identity-token scope, Environment, restored cache or primary-artifact access; the protected job never checks out PR code, derives the latest complete immutable stable base itself, and accepts only the byte-identical canonical manifests plus all 53 payloads from the two exact-head, secret-free build jobs before key provisioning. After signing, all four apps must pass RSA-PSS verification against the reviewed production-authority pin before either artifact or Pages publication. The workflow names the hardware artifact with PR plus the full head SHA; the flash consumer selects that exact name and accepts the display version only from its source-SHA-bound metadata. PR code executes only in unprivileged jobs. Final state/SHA/label checks bind both uploads; cleanup and reconciliation share the per-PR lock. |
| Transactional key rotation + VIN transition journal | `patches/tesla-ble/0002-report-key-regeneration-result.patch`, `main/vehicle_pairing.cpp`, `logic/key_rotation.hpp`, `logic/vin_transition.hpp`, `main/main.cpp` | Reporting a failed private-key rotation as successful, reusing old sessions after a durable replacement key, or a power cut leaving a new VIN paired with the previous vehicle's key/session state. The prior in-memory key is restored on persistence failure; `tesla_ble/key_rotate` blocks boot/signing until cleanup completes (and an unreadable marker probe fails closed); `tesla_cfg/vin_txn` drives deterministic recovery across namespaces. |
| Tesla protocol and patch known-answer gate | `test/tesla_protocol_vectors.test.mjs`, `patches/tesla-ble/`, `dependencies.lock.*` | A dependency or local patch preserving compilation while changing Tesla's VIN advertisement hash, P-256 ECDH byte order, `session info` HMAC label, AES-GCM metadata/AAD/nonce/tag layout, anti-replay early return, transactional key regeneration, or RX-framing log-flood protection. Patch 0003 additionally pins separate hourly warning/error clocks, saturating suppression, reset order, severity and all six callsites. Patch 0004 is the one size-motivated member of the series -- it deletes the five unsent Parental Controls arms from the `CarServer_VehicleAction` oneof so `--gc-sections` can reach their descriptors -- and is pinned as a pure deletion whose removed arms stay disjoint from the tags `main/vehicle_commands.cpp` builds, so a trim can never silently drop a command the firmware sends. Public canonical test keys are used; no device or vehicle secret enters CI. |
| Generation-bound deferred BLE command readiness | `logic/ble_readiness.hpp`, `logic/ble_deferred_event.hpp`, `main/ble_client.{cpp,hpp}`, `main/vehicle_ctrl.cpp`, `main/vehicle_telemetry.cpp` | Treating a GAP connection handle as command-ready before Tesla service/characteristic discovery, CCCD acknowledgement and a successful task-owned `Vehicle::set_connected(true)`, re-entering allocating/throwing Vehicle/NVS code from the hidden NimBLE host, or applying stale RX after handle reuse. The host copies bounded LinkUp/LinkDown/RX records into a static queue; `vehicle_loop` rejects stale generations, applies ordered down barriers and publishes readiness only after Vehicle acknowledges the exact generation. Overflow, oversize RX or an exception drops the link fail-closed. Persistent telemetry callbacks likewise publish trivially-copyable latest values; parsing and cache strings happen after the Vehicle lock is released. A separate fixed current-feedback generation preserves `set_charging_amps` readback-before-command-completion semantics. |
| Acknowledged NimBLE host startup + sticky reset evidence | `logic/nimble_start_gate.hpp`, `main/ble_client.{cpp,hpp}`, `main/main.cpp`, `main/ota_update.cpp` | Treating ESP-IDF 5.5's void `nimble_port_freertos_init()` wrapper as proof that its hidden host task was created, reopening runtime after a late sync callback, or confirming OTA after the admitted host reset. Boot waits for the real sync callback with a bounded terminal gate; the per-boot reset counter saturates and OTA health rechecks both sync and unchanged reset evidence. |
| Downgrade gate | `main/ota_update.cpp` | A signed but OLD image carrying a since-patched flaw. A signature proves authenticity, not freshness. |
| Manifest ↔ image version match | `main/ota_update.cpp` | The manifest and the `.bin` being separately-controlled artifacts: a host advertising 1.9.0 while serving 1.8.0 would install a build nobody published. Both must name the same version, and the manifest is re-fetched on the update path so a direct caller is gated too. |
| Bounded exact OTA manifest intake | `logic/ota_contract.hpp`, `main/ota_manifest.hpp`, `main/ota_update.cpp` | A truncated/chunked/lying response, duplicate `version`, trailing JSON, over-nesting, decoded U+0000, huge numeric core or attacker-sized version turning an update check into ambiguity, integer overflow or contiguous-heap failure. The transport accepts only a complete non-empty body up to 8192 bytes, fixed responses must exactly match Content-Length, syntax is allocation-free before cJSON, every decoded root key is unique, and the canonical version is validated at ≤31 bytes before copy. One bounded reserve plus early body release bounds peak allocation; host state-machine and pinned-cJSON OOM/duplicate cases gate the production path. |
| Coherent allocation-free OTA status lock | `main/ota_update.cpp`, `test/test_runtime_boundary_contract.py` | A first-use lock allocation failure exposing shared status without protection, mixed-generation state/message/version fields, or `std::string` allocation while the OTA status mutex is held. Readers copy one fixed POD/array snapshot under the lock; a completed manifest check or check error replaces all public fields with one fixed candidate, while progress-only transitions remain serialized by the same lock. Strings materialize only after unlock; CAS-loser cleanup, read/write lock-failure matrices and partial-check-publication mutation canaries fail closed. |
| Bug-report redaction | `logic/redact.hpp`, `GET /status?redact=1`, `GET /diag?redact=1` | A diagnostic snapshot carrying the reporter's VIN, SSID, IP, vehicle/nearby BLE MACs, broker or syslog host into a public issue. Fails closed; substitutes the value and keeps the key. The physical controller's `sys.board_mac` deliberately remains visible. `/status` redacts by field; `/diag` uses fixed-buffer whole-line framing, discards a wrapped ring's markerless first fragment, and collapses any >288-byte logical line to `<redacted>` so marker/value seams cannot leak. The line table still has to cover every private-value log statement, including the request URI carrying the VIN; a new VIN/SSID/host-bearing log line needs a rule and test in the same commit. |
| Device-bound browser mutation gate | `logic/http_origin.hpp`, `main/http_server.cpp` | A foreign or DNS-rebinding website borrowing a LAN user's browser to trigger key rotation, reconfiguration, commands, diagnostic erasure or OTA. Browser mutations fail before dispatch unless Host is the device name/current IP and Origin matches it; the policy covers every POST plus state-changing legacy GET forms. Headerless evcc/curl traffic preserves the intentionally unauthenticated trusted-LAN contract. This is browser-CSRF hardening, not authentication of raw LAN peers. |
| Private wake capture | `scripts/capture_wake.py` | A full VIN and raw authenticated BLE frames landing as a commit-ready 0644 logfile. Default capture is VIN/frame-redacted in a fresh 0700 temp directory with a 0600 file; full bytes require explicit `--include-sensitive`, and verbose logging is disabled in `finally`. |
| Restricted setup-AP surface | `main/provisioning.cpp` | The open setup AP exposing `/gen_keys`, `/diag`, `/status` or the command API. Only the provisioning routes are registered in AP mode. |
| Charging-Manager-only key role | `vehicle_pairing.cpp` | Enrolling a key with door/body privilege the integration does not need. |

No HTTP auth or TLS on the device API, by design — evcc cannot send credentials, so the device is
trusted-LAN only. See [`SECURITY.md`](SECURITY.md).

## 4. Network

| Feature | Where | Prevents |
|---|---|---|
| Captive portal | `main/provisioning.cpp`, `logic/captive.hpp` | A setup portal that does not pop. A DNS catch-all, a **302 redirect** on the three OS probe paths (a 200 + page is a heuristic Android may leave undecided), and the RFC 8910 DHCP option 114 — three independent ways for a client to find it. |
| SPI Ethernet (W5500) | `net.cpp` (`CONFIG_TESLA_ETH_ENABLED`), `main/Kconfig.projbuild`, `sdkconfig.defaults.esp32s3` | Having to run the BLE proxy on a radio that must share ONE antenna path with BLE. On a wire the WiFi stack is never started — no coexistence arbitration, no `WIFI_PS_MIN_MODEM` tax on every GATT round-trip, and its heap stays free. Polling mode (no INT line on the ATOMIC PoE Base), a positive VERSIONR probe, and a bounded lease wait that falls back to WiFi rather than stranding an unplugged board. Every partial-start failure unwinds handlers, publication, glue, netif, driver, PHY/MAC, event group and SPI in reverse ownership order; a failed driver uninstall leaves its dependent tail intact and fails boot instead of manufacturing dangling callbacks. |
| One image, four boards | `main/board.{cpp,hpp}`, `main/net.cpp` (`kEthCandidates[]`) | Two independent copies of "which board is this" answering differently on a SHARED pin: the T-Dongle-S3's panel clock is GPIO5, which is the PoE base's SPI SCLK. One cached detector, and the Ethernet probe is refused on a detected T-Dongle. The W5500 itself is found by trying each known wiring in turn (ATOMIC PoE Base, then Waveshare ESP32-S3-ETH) — its `VERSIONR` answer is the board ID. |
| Transport seam | `main/net.hpp` + `main/net.cpp`, `logic/net_link.hpp` | A network layer that can only ever be WiFi. ONE contract (`net_is_up` / `net_kind` / `net_active_netif`) replaces a predicate hand-`extern`ed in five modules and a `"WIFI_STA_DEF"` ifkey hardcoded in three — each correct only while a radio was the sole transport. |
| Gateway ICMP watchdog | `net.cpp` `net_watchdog_task`, `logic/net_link.hpp` `watch_step()` | The "ghost association" that fires no disconnect event: the stack believes it is connected, the AP forwards nothing, and no reconnect handler ever runs. The decision — including the baseline rule that a gateway which has NEVER answered ICMP must not trigger recovery — is host-tested, not an `if` inside a task loop. |
| Generation-owned ICMP probe lifetime | `logic/ping_probe.hpp`, `main/ping_probe.hpp`, `main/net.cpp`, `main/syslog.cpp` | A timed-out asynchronous esp_ping worker calling into a dead stack frame, a stopped handle being deleted/reused before `on_ping_end`, or a late callback completing a newer probe. Network-watchdog and Syslog probes share one persistent lifecycle: timeout requests stop, missing end quarantines the exact generation as PendingEnd, cleanup/reuse waits for its matching callback, and stale generations cannot wake a replacement waiter. |
| Endless runtime reconnect | `net.cpp` `wifi_event_handler` | Surrendering to the setup portal on a transient outage once the credentials are known-good. |
| mDNS + DHCP hostname with privacy-bounded TXT | `main.cpp` | Having to find the IP, or making the full vehicle VIN multicast-browseable during service enumeration. Both names agree on `tesla-key-esp32.local`; mDNS TXT carries version only. |
| Negotiated-MTU BLE writes | `logic/ble_chunk.hpp`, `main/ble_client.{cpp,hpp}` | Paying twelve fixed inter-chunk delays for a 244-byte message after ATT negotiated MTU 247, while still preserving the mandatory 20-byte fallback before MTU exchange and across reconnect generations. |
| SNTP + browser-clock fallback | `main.cpp`, `POST /set_time` | A 1970 clock, which makes tesla-ble reject every persisted session and breaks OTA TLS date validation. |

### Why there is no static analyser (measured, not assumed)

Read this before proposing one. Measured on this tree with clang-tidy 18:

- **Blanket config**: 3355 findings, dominated by noise — 769 `llvmlibc-callee-namespace`, 599
  `altera-unroll-loops`, and 598 `pro-type-vararg` + 593 `avoid-do-while` which are almost entirely
  this project's own `CHECK` macro.
- **Curated to bug-finding checks** (`bugprone-*`, `clang-analyzer-*`, `cert-*`, `performance-*`):
  **3 findings, ZERO of them in `main/logic/`**. Two are `cert-err33-c` on `snprintf` in the test
  file's golden emitter (the return is the length it *would* have written, into a fixed buffer);
  one is `bugprone-easily-swappable-parameters` on a test lambda.
- **`-Wconversion`**: 3 hits, all `int`→`float` in the two colour-gradient `lerp8` helpers, exact
  over the value range they are called with. **`-Wshadow`, `-Wsign-conversion`**: zero.

The yield is this low for a structural reason visible in the code: the bug classes are typed out
rather than linted out, and the defects this project actually ships fixes for — a wrong link-state
transition, a stale cache served as fresh, a heap budget — are not in a linter's language. So there
is deliberately **no `.clang-tidy` file**: an inert config reads like a guarantee while doing
nothing.

What the survey *did* find was the opposite gap. `main/logic/` was never the exposed half — it has
`-Wall -Wextra -Werror` and 3400+ host-tested checks. `main/*.cpp` was, and it carried no warning
policy of its own. That is now pinned in `main/CMakeLists.txt`.

The root `CMakeLists.txt` still appends `-Wno-error=format` because the managed tesla-ble dependency
prints `uint32_t` with `%u`. `main/CMakeLists.txt` then re-arms `-Werror=format` privately for the
repository-owned firmware component, so upstream warnings remain visible without weakening the
format contract on our own code across all four targets.
